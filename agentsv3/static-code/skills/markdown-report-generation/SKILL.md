# Skill: Markdown Report Generation

## Purpose

Convert repository findings into a concise markdown report with clear sections and severity labels.

## Use When

- Producing a code review or analysis summary
- Writing a repository report from multiple findings
- Presenting risks, priorities, and next steps in markdown

## Output Format

Use a markdown report with:

- Repository summary
- Findings grouped by category
- Severity labels
- File references where relevant
- Recommended next steps

## Writing Rules

- Keep language concise and specific
- Separate confirmed findings from recommendations
- Avoid generic filler text
- Prefer direct file references and observable evidence

## Do Not

- Do not invent findings to fill sections
- Do not write long prose when bullets are clearer
- Do not over-quote source files
